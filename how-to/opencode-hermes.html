opencode and Hermes on the Mac

The Spark’s models in opencode and Hermes: one command writes both providers from the registry, with your key by reference.

(Added 2026-10-14, with the spark clients opencode and spark clients hermes generators.)

pi on the Mac sets up what all three clients share: your shell exports SPARK_API_KEY, and make tunnel forwards the Spark’s models to 127.0.0.1:9100. This page adds opencode and Hermes to that. Both reach the Spark the way pi does, through the tunnel, with the key by reference, never written into their files.

1. Write the providers

On the Mac, from your clone of this repo:

make clients

It writes the spark provider for pi, opencode and Hermes from the registry: each chat model by its real name, with its context window. For one client alone: make clients-pi, make clients-opencode or make clients-hermes. Each keeps everything else in its file, keeps the previous file beside it as a .bak with the same permissions, and says which.

  • opencode: ~/.config/opencode/opencode.json, provider spark, key {env:SPARK_API_KEY}. Each model gets its context and output limits, so opencode knows how much context is left, and the reasoning efforts it can be sent (below, under opencode’s reasoning effort). A config with comments in it (JSONC) is refused, not rewritten: then copy the provider in by hand from what uv run --frozen --project spark spark clients opencode prints.
  • Hermes: ~/.hermes/config.yaml, under providers.spark, with key_env: SPARK_API_KEY. Hermes keeps the default model it had. The file is rewritten from its settings, so comments in it don’t survive; the .bak keeps them.

2. Pick a model

  • opencode: /model, then a spark/… model, such as spark/qwen3.8-27b.

  • Hermes: /model custom:spark:qwen3.8-27b in a chat. To make a Spark model Hermes’s default instead, on the Mac, from your clone:

    uv run --frozen --project spark spark clients hermes --write --default qwen3.8-27b

The tunnel has to be open while you use them: make tunnel in a spare terminal.

Hermes’s reasoning effort. Hermes sends its own reasoning effort with every request, and Qwen3.8’s chat template takes only xhigh, its default, medium and low: anything else, such as Hermes’s max or ultra, comes back as an error 500 naming the effort. So make clients sets xhigh for each Spark model, under agent.reasoning_overrides in Hermes’s config, and your other providers keep your global setting. For quicker, shorter thinking in one session, /reasoning medium or /reasoning low; leave out --global, which would change it for every provider.

opencode’s reasoning effort. opencode gives each model a list of efforts to pick from and sends the one you pick. For a provider like this one its own list is low, medium and high, and Qwen3.8’s template refuses high: Error: Unexpected reasoning effort high. So make clients gives each Spark model its own list, low, medium and xhigh, which replaces opencode’s. Default sends no effort at all, and the template then uses its own default, xhigh, the most thinking: so default and xhigh are the same. Gemma’s template ignores the effort. (Added 2026-10-14, checked with opencode 2.0.25 against a stand-in server that recorded what each choice sent: high is now refused inside opencode, before anything is sent.)

If opencode says Unauthorized

opencode 2 runs one background service, and every opencode window you open hands its requests to it. The service has the environment it started with. A key you added to ~/.secrets after it started isn’t in it, so opencode sends an empty key, and the Spark answers 401: opencode shows Error: Unauthorized. A new terminal doesn’t help, because the new window uses the same old service. Restarting the service from a shell that has the key does.

On the Mac, in a terminal opened after the key went into ~/.secrets:

opencode service restart

Then start opencode again. Other opencode windows were using the old service: start one again if it stops answering. opencode service status shows the service’s address when it’s running, and opencode --standalone runs one window with a private service of its own, leaving the shared one alone. (Seen 2026-10-14: the service had started that morning, before the fast coder’s key was made, and a new terminal still got 401 until the restart.)

If Hermes says 401

The key is wrong or missing. Hermes reads SPARK_API_KEY from its environment, so start it from a shell that exports it (the check is on pi’s page). An earlier version of make clients wrote a placeholder line, SPARK_API_KEY=your-llama-swap-key-here, into Hermes’s .env file, and Hermes sends that instead of your key. make clients now says if that line is still there: delete that one line in your editor. The file holds your other keys, so don’t print it.

Not for Claude

Claude Code and Claude Desktop never use these providers: the repo’s first rule keeps the Claude path untouched.
